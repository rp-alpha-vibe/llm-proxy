llm-proxy

HTTP-модуль защиты персональных данных между системой-потребителем и LLM: обнаружение, маскирование, обратимое восстановление.

POST /process → { "result": "..." }

Задача

Что закрываем

  • Найти обязательные типы ПД без лишних false positives
  • Замаскировать их до LLM и восстановить в ответе
  • Держать политики по потребителям и сессии в Redis
  • Выдержать локальный нагрузочный профиль 1000 RPS
Архитектура

Минимальный runtime

  • FastAPI + Uvicorn workers
  • Redis 7 для AES-GCM session state
  • Consumer из LLM_PROXY_DEFAULT_CONSUMER_ID + YAML policies
  • Без обязательного auth header в теле запроса тестера

Один deploy: app + private Redis. Собственный TLS не обязателен: tester допускает HTTP.

Контракт

Единственный публичный API

POST /process

Request: {"payload": "...", "payload_id": "..."}

Response: {"result": "..."}

  • Новый текст → mask
  • Повтор исходного → та же mask (retry)
  • Точная mask → original
  • Перегрузка → 429 + Retry-After
Качество и безопасность

Локальные доказательства

  • 46 синтетических fixtures: локальный F1 1.0, round-trip 1.0
  • Не официальный span-based scoring Альфы
  • Сессии шифруются AES-GCM; ключ только из окружения
  • Сырые ПД не пишутся в логи и metric labels

Как запустить

  1. Скопировать .env.example → .env, задать ключ шифрования
  2. Оставить consumer alfa_tester (ключ секции systems)
  3. docker compose up --build -d
  4. Проверить /healthz и POST /process
