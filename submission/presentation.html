llm-proxy

Защита персональных данных при работе с искусственным интеллектом.

Мы заменяем чувствительные сведения перед отправкой запроса языковой модели и восстанавливаем их в готовом ответе. Модель не получает исходные данные.

https://llm-proxy-production-84c7.up.railway.app

Задача и решение

Зачем нужен сервис

Приложения обращаются к языковым моделям с пользовательским текстом, в котором могут встречаться номера документов, адреса и другие персональные данные.

  • Находим сведения о конкретном человеке, учитывая контекст.
  • Временно заменяем их обозначениями, понятными для дальнейшей обработки текста.
  • Восстанавливаем известные значения в ответе модели, сохраняя весь новый текст.

llm-proxy не обращается к модели самостоятельно. Это делает приложение, которое использует наш сервис.

Пример

Замена и восстановление

ЭтапТекст
Исходный запросНапишите на ivan@example.com.
После заменыНапишите на <EMAIL_1>.
Ответ моделиОтправьте сообщение на <EMAIL_1> сегодня.
После восстановленияОтправьте сообщение на ivan@example.com сегодня.

Адрес в примере вымышленный. Соответствия временно сохраняются в зашифрованном виде. Неизвестные обозначения сервис не угадывает.

Принцип работы

Краткая архитектура

  1. Приложение отправляет текст в POST /process.
  2. Наш сервер на Python и FastAPI определяет персональные данные и заменяет их.
  3. Приложение самостоятельно отправляет очищенный текст языковой модели.
  4. Полученный от модели ответ приложение повторно передаёт нашему сервису, который восстанавливает известные значения.

Redis служит временным зашифрованным хранилищем соответствий. Публичное развёртывание: приложение и закрытый Redis на Railway.

Проверка

Как обратиться к сервису

Один адрес используется и для замены, и для восстановления данных: POST /process.

Запрос: {"payload": "текст", "payload_id": "уникальный идентификатор"}

Ответ: {"result": "обработанный текст"}

При восстановлении передайте ответ модели с тем же payload_id. Если повторить исходный запрос, сервис вернёт прежнее маскирование.

Демонстрация: https://llm-proxy-production-84c7.up.railway.app/docs. Для испытаний используйте только вымышленные данные.

Качество и безопасность

Что проверено

  • Поддерживаются обязательные категории персональных данных из задания хакатона.
  • Локальный набор из 46 вымышленных примеров: F1 = 1,0 (показатель точности поиска), точное восстановление исходного текста во всех соответствующих проверках.
  • Соответствия хранятся временно и шифруются. Исходные данные не должны попадать в технические журналы и показатели.
  • Для разных приложений настраиваются категории данных и право на восстановление.

Результаты локальной проверки не заменяют оценку организаторов на их тестовом наборе.

Демонстрация и исходники

Где посмотреть и как запустить

Публичный сервис: https://llm-proxy-production-84c7.up.railway.app

Исходный код: https://github.com/rp-alpha-vibe/llm-proxy (для закрытого репозитория требуется доступ).

Для локального запуска: скопируйте .env.example в .env, задайте ключ шифрования и выполните docker compose up --build -d. Подробные шаги и примеры запросов приведены в README.

Открытая проверка: совместимость с официальной тестовой системой организаторов. Railway используется для функциональной демонстрации; целевой нагрузочный профиль подтверждён только локально.
