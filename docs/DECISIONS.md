# Decisions

Здесь фиксируются только решения, которые реально влияют на архитектуру, безопасность, acceptance или способ работы команды.
Локальные технические детали сюда не заносятся.

## D-001 — Lightweight AI development process

Status: accepted

Decision:

- использовать короткий цикл Goal -> Plan -> Acceptance -> Implement -> Test -> Review -> Accept;
- не переносить в проект многоступенчатые manifests, evidence-only commits, обязательные ADR и независимые review для стандартных задач;
- requirements/architecture документы создавать только когда они закрывают реальную неоднозначность или риск;
- separated self-review допустим для стандартных изменений;
- independent review нужен только для высокорисковых изменений.

Reason:

Хакатон ограничен по времени. Процесс должен предотвращать дорогие ошибки, но не становиться отдельной работой.

## D-002 — Repository as project memory

Status: accepted

Decision:

Ключевые требования и важные решения должны жить в репозитории, а не только в истории чатов.

Reason:

Проект будет разрабатываться несколькими AI-инструментами и сессиями; без общего источника истины быстро появляется drift.
